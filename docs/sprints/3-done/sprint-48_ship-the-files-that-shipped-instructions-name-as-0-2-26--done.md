**What actually failed.** Pipeman's own commands kept to the publish-isolation rule. The rule has an unguarded hand-off: when npm needs a human for authentication, the irreversible command is re-run by a person, in whatever directory their terminal is in. The pre-publish checks (`verify-tarball.sh`, a pinned HEAD) all ran against a tree that was not the one published. "Pipeman screwed up" is not what the record shows, and neither is Master Controller's round-2 note.

**For whoever continues this framework (Jamboree), not decided here:** the fix is making the human-auth path unable to publish anything but the verified bytes. Candidate approaches, none measured here, to be decided deliberately: Pipeman obtains the OTP and runs `--otp` itself; the hand-off is one copy-paste command with an absolute `cd <clone> &&` prefix; or Pipeman packs once, records the shasum, and the hand-off publishes that exact `.tgz`. The last one has a known cost: publishing a tarball omits `gitHead` (per the v0.2.11 tag annotation and sprint 13, npm reads it from the working directory's git; re-measure before relying on this). No release of fully-completely is planned to carry any of these (the user's freeze decision, D-013 on FMC's side).
